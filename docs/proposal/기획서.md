## 1. 앱 한 줄 소개

**RideTune — 휴대폰에서 한 번 설정한 나의 감각 프로필로, 차가 소리·빛·공기를 내게 맞춰 주는 감각 민감 탑승자용 차량 앱**

## 2. 기획 배경

**주목한 사람**
자폐 스펙트럼, 외상 후 스트레스(교통사고 트라우마 포함), 청각과민, 편두통, 감각처리장애 등으로 **소리·빛·온도·예측하지 못한 변화에 민감한** 운전자와 동승자.

**불편한 순간**
- 갑자기 울리는 경고음·단속 카메라 안내음에 놀라 운전이 흔들리거나, 뒷좌석 아이가 패닉에 빠진다.
- 터널 출입, 맞은편 전조등, 강한 햇빛처럼 밝기가 갑자기 바뀌는 순간이 힘들다.
- 공조 바람 소리, 외부 소음, 실내 냄새가 쌓여 이동 내내 피로하다.
- 힘든 순간이 와도 운전 중에는 여러 설정을 하나씩 바꿀 수 없다. 탈 때마다 설정을 다시 맞춰야 하고, 남의 차·공유차에서는 더 어렵다.

**왜 해결해야 하는가**
- 차 안은 피할 곳이 없는 닫힌 공간이라 감각 자극이 그대로 쌓인다. 이동 자체를 피하게 되면 통학·통근·치료 방문 같은 일상이 제한된다.
- 운전자가 놀라거나 동승자가 패닉에 빠지면 곧 안전 문제가 된다.
- 지금 차량 설정은 "평균적인 사람"에 맞춰져 있다. 민감한 부분은 사람마다 다르므로 **개인 프로필**이 필요하다.

> 심사 포인트 — 창의성: Pain Point가 구체적인 순간으로 정의되어 있고, 해결 방식(프로필 → 자동 적용)이 명확한가

## 3. 앱 주요 기능 및 차량 특화 요소

| # | 기능 | 해결하는 문제 | 쓰는 차량 데이터 / 기능 |
|---|---|---|---|
| 1 | **감각 프로필 (휴대폰)** — 소리·빛·온도/공기·예측 불가능한 변화 중 무엇에 민감한지, 정도와 편안해지는 방법을 설문형으로 설정 | 운전 중엔 설정할 수 없고, 탈 때마다 다시 맞춰야 함 | — (휴대폰에서 입력) |
| 2 | **탑승 시 자동 적용** — 프로필이 차에 올라가면 실내 환경을 한 번에 맞춤 | 차를 바꾸거나 탈 때마다 여러 메뉴를 조작해야 함 | Vehicle SDK: 무드등 밝기·색, 실내등·독서등, 스마트글라스 투과도, 공조 온도·풍량·내기순환, 창문, 시트 열선·통풍 |
| 3 | **미리 알려 주기** — 놀랄 만한 소리·변화 직전에 짧고 부드러운 음성으로 먼저 예고 | 갑작스러운 경고음·안내음에 놀람 | NaviHelper 안전 이벤트(단속 카메라·주의 구간), TextToSpeech SDK, Vehicle SDK(방향지시등·와이퍼 상태) |
| 4 | **진정 모드** — 버튼 하나 또는 음성("좀 힘들어")으로 즉시 자극을 낮춤: 조명 낮추기, 창문 닫기, 내기순환, 풍량 줄이기, 쉴 곳 안내 | 힘든 순간에 여러 설정을 하나씩 바꿀 수 없음 | SpeechToText SDK, Vehicle SDK 제어, NaviHelper(휴게소·졸음쉼터 검색 화면) |
| 5 | **좌석별 맞춤** — 감각 민감 동승자가 앉은 좌석 쪽 조명·공조·시트를 따로 조절 | 운전자와 동승자의 민감도가 다름 | Vehicle SDK 좌석 점유·좌석별 공조·시트, TextToSpeech 오디오 존 지정 |
| 6 | **주행 후 돌아보기 (휴대폰)** — 진정 모드를 쓴 시점·상황을 보여 주고 프로필 보정을 제안 | 무엇이 힘들었는지 기억하기 어렵고 프로필이 고정됨 | 주행 중 이벤트 기록(위치는 저장하지 않음) |

**휴대폰 대비 차량에서만 가능한 가치**
- 휴대폰 앱은 "알려 주기"까지만 할 수 있지만, RideTune은 **차량 자체(조명·유리·공조·창문·시트)를 바꿔** 자극을 직접 줄인다.
- 주행 상황(안전 이벤트, 방향지시등, 와이퍼)을 알기 때문에 **자극이 오기 전에** 대응할 수 있다.

> 심사 포인트 — 차량특화성: 모바일 대비 차량에서만의 가치가 있는가, 주행·정차 맥락과 차량 기능에 유기적으로 결합되었는가

## 4. 주요 사용 시나리오

**시나리오 A — 교통사고 이후 경고음에 예민해진 운전자**
1. 휴대폰 RideTune에서 "갑작스러운 경고음·안내음"에 '매우 민감', "밝기 변화"에 '조금 민감'으로 설정한다.
2. 차에 타서 RideTune을 켜면 프로필이 적용된다. 무드등은 은은한 색·낮은 밝기, 스마트글라스는 눈부심을 줄이는 쪽으로 맞춰진다.
3. 단속 구간에 가까워지면 경고음보다 먼저 "곧 단속 카메라가 있어요"라고 낮은 목소리로 예고해, 이어지는 안내음에 놀라지 않는다.

**시나리오 B — 자폐 스펙트럼 아이를 뒷좌석에 태운 부모**
1. 부모가 휴대폰에서 아이의 프로필(큰 소리·바람 소리에 민감, 시원한 온도 선호)을 만든다.
2. 아이가 뒷좌석에 앉으면 그 좌석 쪽 풍량을 낮추고 온도를 조금 낮춘다.
3. 아이가 불안해하면 부모가 "진정 모드"를 말한다 → 창문이 닫히고 내기순환으로 바뀌며 조명이 낮아지고, 가까운 졸음쉼터 안내 화면이 뜬다.
4. 도착 후 휴대폰에서 "오늘 14:20 진정 모드 사용 — 고속도로 진입 직후"를 확인하고 프로필을 조정한다.

## 5. 개발 계획

| Pleos SDK / API | 쓰는 곳 |
|---|---|
| Vehicle SDK — Light | 무드등 밝기·색, 실내등·독서등 끄기/켜기 |
| Vehicle SDK — Window | 스마트글라스 투과도, 창문 닫기 |
| Vehicle SDK — HVAC / Seat | 온도·풍량·내기순환, 좌석별 시트 열선·통풍, 좌석 점유 확인 |
| Vehicle SDK — TurnSignal / Wiper | 갑작스러운 소리·움직임이 생기는 순간 감지 |
| NaviHelper SDK | 안전 이벤트(단속 카메라·주의 구간) 수신 → 예고, 휴게소·졸음쉼터 검색 화면 열기 |
| TextToSpeech SDK | 예고·안내 음성(낮고 짧게), 좌석 오디오 존 지정 |
| SpeechToText SDK | 음성으로 진정 모드 켜기 |

- **개발 환경**: Android(Kotlin, Jetpack Compose), minSdk 28, Pleos Car Emulator로 구동 검증
- **휴대폰 → 차량 프로필 전달**: _(방식 결정 필요 — 아래 "결정할 것" 참고)_
- **1차 제출 시점(11/15) 구현 범위**: 차량 앱에서 프로필 선택 → 자동 적용(조명·공조·창문), 진정 모드 버튼, 에뮬레이터 시연 영상
- **2차 PT(12/3~4)까지 구현 범위**: 휴대폰 프로필 설정 + 차량 전달, 미리 알려 주기(NaviHelper·TTS), 음성 진정 모드(STT), 좌석별 맞춤
- **개인정보**: 민감도 프로필은 건강 정보에 가까우므로 진단명을 묻지 않고 "무엇이 힘든지"만 받는다. 기록에 위치는 저장하지 않는다.
- **유의**: Vehicle SDK 제어 권한은 Pleos App Market과 사전 협의·승인된 경우에만 실제 배포 가능(공모전 시연은 에뮬레이터 기준).

> 심사 포인트 — 기술 활용성: Pleos SDK·API를 앱의 핵심 기능과 경험에 적절히 활용했는가

## 6. 기대효과 및 발전 가능성

**사용자 가치**
- 감각 민감 운전자·동승자가 이동을 덜 두려워하고, 놀람·패닉으로 인한 위험 순간을 줄인다.
- 보호자는 운전에 집중하면서도 동승자를 돌볼 수 있다.

**타깃 고객**
- 1차: 감각 민감 당사자(운전자) 및 감각 민감 아동·가족을 태우는 보호자
- 2차: 편두통·청각과민 등 일시적·경미한 민감 사용자, 고령 운전자
- 확장: 장애인 이동 지원 차량, 택시·공유차(프로필을 들고 다니는 형태) `[확인 필요: 국내 등록 장애인 수, 자폐 스펙트럼·PTSD 유병률 등 통계와 출처]`

**예상 MAU / Retention** `[확인 필요: 산정 근거]`
- 예상 MAU: _(타깃 인구 × Pleos 탑재 차량 비율 × 설치율로 산정)_
- Retention: 이동은 매일 반복되고, 프로필이 쌓일수록 바꾸기 어려워 높은 재사용 기대 _(수치는 근거와 함께)_

**향후 확대 계획**
- 차량을 바꿔도 같은 프로필이 따라가는 계정 연동(가족 차·렌터카·카셰어링)
- 기관 연계: 특수학교 통학 차량, 치료센터 이동 지원
- 감정·생체 신호(웨어러블) 연동으로 진정 모드 자동 제안

> 심사 포인트 — 사업성: 타깃 고객이 명확하고 사용자 확보·지속 이용·확대 가능성이 있는가

## 결정할 것 (제출 전 지울 것)

1. **휴대폰 → 차량 전달 방식**
   - (추천) 차량 화면에 QR 표시 → 휴대폰으로 스캔해 웹 설정 페이지에서 프로필 작성 → 서버를 거쳐 차량이 받음. 휴대폰 앱 설치가 필요 없어 1차 시연까지 빠르게 만들 수 있다. 작은 서버(예: Firebase)가 필요하다.
   - 휴대폰 Android 앱 + 서버: 완성도는 높지만 앱이 두 개라 5일 안에는 어렵다.
   - 1차는 차량 앱 안에서 프로필 설정만 하고, 휴대폰 연동은 기획서에 계획으로만 적는다.
2. **소리를 직접 줄이는 기능**: 차량 전체 볼륨·경고음을 바꾸는 공개 API는 찾지 못했다. 그래서 지금은 "예고"와 "외부 소음 차단(창문·내기순환)"으로 대응한다. 설명회 다시보기나 문의로 확인할 가치가 있다.
