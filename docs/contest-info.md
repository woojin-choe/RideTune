## 1. 공모전 개요

- 차량 데이터와 기능, 이동 상황을 활용해 운전자와 탑승자에게 새로운 경험을 제공하는 앱 서비스를 발굴하고 개발하는 공모전
- 출퇴근, 여행, 충전, 주차, 가족과의 이동, 반려동물 동반, 휴식, 업무 등 차량을 이용하는 다양한 순간 — 고객의 이동 과정에서 필요한 서비스를 자유롭게 제안
- 자동차는 이동 수단이자 위치·경로·주행 상태·차량 상태 등 다양한 데이터와 기능을 제공하는 디지털 플랫폼

| 항목 | 내용 |
|---|---|
| 주최 | 현대자동차그룹 |
| 운영 수탁사 | 주식회사 스터닝 (접수양식 개인정보 처리위탁 안내 기준) |
| 접수 기간 | 2026.10.21(수) ~ 11.15(일) 23:59 (23:59는 접수양식 기재) |
| 총상금 | 5,100만원 (+ 숏폼 챌린지 50만원 별도) |
| 선정 규모 | 10팀 (현대자동차그룹 행사 전시·시연, 2027.02) |
| 지원 방법 | 접수양식(기획서) 이메일 제출 |
| 참가비 | 무료 (접수양식 동의서 D항) |

### 심사 단계
- **1차 · 서류심사**: 접수양식(기획서) 제출 → 접수 마감 후 서류심사로 2차 PT 대상팀 선정 (공지사항 기준 **20팀**)
- **2차 · 최종 PT 심사 (오프라인 발표)**: 기획한 앱의 핵심 기능을 구현해 발표 → 최종 선정 결과 발표

### 고객 니즈 · 페인포인트 예시 (주제 한정 아님, 주제 구분 없이 자유 지원)
- **모빌리티 & 라이프 편의**: 주행 중에도 끊김 없는 주문 · 픽업 · 주차 등 일상 서비스 경험
- **인카 엔터테인먼트**: 주행 맥락과 결합된 몰입형 미디어 · 사운드 경험
- **스마트 드라이빙 & 안전**: 차량 이상 징후의 조기 인지와 실시간 안전운전 피드백
- **패밀리 & 동승자 케어**: 장거리 이동을 즐겁게 만드는 어린이 · 가족 동승자 케어
- **그 밖의 주제**: 이 외 주제도 자유롭게 출품 가능

## 4. 지원 · 제출 방법

### 접수 절차
1. **양식과 제출물 준비** — 접수양식·개인정보 수집·이용 동의서 다운로드 (DOCX: https://appdevchallenge.auto-hmg.io/downloads/contest-application-consent.docx)
   - 접수양식이 곧 기획서
   - 시연 영상, GitHub 저장소, APK는 선택 제출, 제출 수준에 따라 가산점
   - 숏폼 챌린지 링크 제출은 선택
2. **참가자 전원 개별 동의** — 개인 참가자 또는 대표자와 팀원 전원이 각각 동의 여부, 서명, 날짜 작성. 대표자는 팀원 전원을 참조(CC)하여 제출 (CC만으로 동의를 대체하지 않음)
3. **이메일 제출**
   - 접수 이메일: **appdevchallenge@hyundai-partners.com**
   - 메일 제목: `[차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`
   - 회원가입 없이 이메일로 제출

### 수정 제출
- 마감 전까지 **처음 제출한 이메일 주소**로 수정 자료 재발송
- 여러 번 제출 시 마감 전 마지막 제출본을 최종본으로 심사
- 메일 제목: `[수정제출] [차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`
- 수정 제출 시에도 전체 제출 자료 + 서명한 동의서 모두 첨부, 팀원 전원 CC

### 제출물
| # | 제출물 | 구분 | 비고 |
|---|---|---|---|
| 01 | 접수양식(기획서) | 필수 | 아이디어와 기획 내용 작성 |
| 02 | 시연 영상 | 선택 (가산점) | 목업 · 프로토타입 · 화면 녹화 인정 |
| 03 | GitHub 저장소 | 선택 (가산점) | 소스 코드 및 APK 포함 |
| 04 | 숏폼 링크 | 선택 (가산점 없음) | 접수양식(기획서)에 기재 |

- 1차 접수 시 시연 영상, GitHub 저장소, APK 등을 함께 제출하면 **단계별 가산점** 부여
- **2차 PT 심사 대상 팀은 PT 심사 전까지 실제 동작 가능한 앱 개발을 완료해야 함**
- 1차 접수 시 제출한 개발 산출물은 2차 PT 심사 전까지 자유롭게 추가 고도화 가능
- APK 파일만 따로 제출하지 말고 GitHub 저장소에 소스 코드와 함께 업로드

### GitHub 저장소 제출 안내
- 새 저장소 생성 또는 기존 개발 저장소 사용, 프로젝트 소스 코드 업로드
- APK는 저장소 내 `apk/` 폴더에 업로드
- APK 파일명: `팀명_앱이름_release.apk`
- 저장소 주소와 APK 파일 경로를 제출
- APK는 실행 가능한 release 버전
- APK가 GitHub 업로드 용량 초과 시 GitHub Releases에 등록 후 Release 페이지 주소 제출
- 비공개(Private) 저장소 가능 — 공지된 심사용 GitHub 계정을 Collaborator로 초대, 마감 전 접근 가능 여부 반드시 확인 (개인 계정 비공개 저장소는 Collaborator에게 쓰기 권한도 부여되므로 초대 전 권한 확인)
- README.md 필수 작성 내용:
  - 앱 이름 및 한 줄 소개
  - 실행 방법
  - 테스트 환경 및 필요한 설정
  - APK 파일 위치 또는 GitHub Release 링크

## 5. 접수양식(기획서) 구성 — DOCX 원문 기준

### 01 참가신청서 (운영 접수용)
- **A. 참가 기본정보**: 참가 단위(개인/팀), 참가 부문(대학(원)생 / 일반(스타트업 포함)), 팀명(개인은 성명), 앱명/프로젝트명, 대표자 성명·역할, 대표자 소속(필수 아님), 대표자 이메일, 대표자 휴대폰번호, 참가 인원, 작성일
- **B. 참가 구성원**: 대표자 포함 전원 — 성명, 소속, 휴대폰 번호, 이메일 주소, 담당 역할
- 운영용 연락정보는 신청서에만 기재. 주민등록번호·신분증·상세주소는 요구하지 않음

### 02 앱 프로젝트 소개 / 심사 자료
※ 대표자·구성원의 성명, 연락처, 이메일, 소속은 기재하지 않음 (01에만 기재). **소개 자료 분량 제한 없음**

1. **앱 한 줄 소개** — 앱을 한 문장으로 소개
2. **기획 배경** — 어떤 고객의 니즈나 불편한 순간에 주목했으며, 왜 해결이 필요한지
3. **앱 주요 기능 및 차량 특화 요소** — 핵심 기능, 어떤 문제를 해결하며 차량에서 어떤 새로운 경험을 제공하는지
4. **주요 사용 시나리오** — 누가, 어떤 상황에서, 어떻게 사용하는지 구체적 이용 흐름
5. **개발 계획** — Pleos Connect 환경에서 앱을 어떻게 구현할지, 주요 개발 범위와 SDK/API 사용 계획
6. **기대효과 및 발전 가능성** — 사용자 가치와 향후 확대·발전 가능성 (타깃 고객 분석, 예상 MAU, Retention Rate, 향후 서비스 확대 계획 등)
7. **참고자료** (선택 · 가산점) — 앱 화면 시안, 시연 영상, GitHub 저장소 등 파일 또는 링크
8. **숏폼 링크** (선택 · 가산점 없음)

- 공유 링크와 첨부자료에도 개인정보·계정정보·개발자 실명이 노출되지 않도록 확인. 필요 시 별지 추가 가능

### 03 개인정보 수집·이용 동의서 / 04 대표자·팀원별 동의 확인 및 서명
- 수집 항목: 성명, 소속, 휴대폰번호, 이메일 주소, 팀원정보(팀 참가 시), 서명
- 보유 기간: 2027.02.28까지 보관 후 파기 / 수상자는 결과 발표일로부터 2년 보유 후 파기
- 동의 거부 시 응모·접수 제한
- 대표자 및 모든 팀원이 각각 동의 여부·서명·서명일자 작성

## 6. 개발 환경

### 요구사항
- Android API 28 이상, Gradle 8.0 이상, Java 또는 Kotlin (Pleos 개발 문서 기준, 대응 SDK 버전도 같은 페이지)

### 플랫폼 용어
- **Pleos**: 현대자동차그룹의 소프트웨어 중심 모빌리티 브랜드
- **Pleos Connect**: 차량용 인포테인먼트 플랫폼
- **Pleos Playground**: Pleos 개발자 포털

### Pleos Connect SDK
| 분류 | SDK |
|---|---|
| 차량 상태 | Vehicle SDK |
| 위치 정보 | FusedLocation SDK |
| 길 안내 연동 | NaviHelper SDK |
| 음성 입출력 | TextToSpeech SDK · SpeechToText SDK |

- 각 SDK의 제공 상태와 사용 조건은 공식 문서에서 확인
- 에뮬레이터 등 개발 도구로 구동 검증 가능

### 예시 시나리오 (참고용, 주제 제한 아님)
- 음성 메모 앱 — SpeechToText SDK로 운전 중 음성을 메모로
- 안전운전 점수 앱 — Vehicle SDK 차량 상태 데이터로 주행 습관 점수화
- 배달 기사용 앱 — NaviHelper SDK로 경로 안내 연동, 배달 동선 지원

### 공식 문서 링크
- Pleos Playground: https://pleos.ai/playground
- 개발 환경 설정 가이드 (에뮬레이터 사용법): https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator
- Pleos Connect SDK 문서: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/
- Pleos Connect SDK API 참조: https://document.pleos.ai/api-reference/connect-sdk-pleos
- Vehicle SDK 튜토리얼: https://document.pleos.ai/docs/pleos-only/tutorial/vehicle-sdk

### FAQ: 개발 시작 방법
- Pleos Connect 환경 이해 → Pleos Playground 개발 문서로 아이디어 기획 → Pleos Connect SDK로 개발
- 공고일부터 공개된 Pleos Playground 개발 문서로 기획·개발 착수 가능

## 7. 심사 기준 (1차 서류심사, 세부 배점 비공개)

| 항목 | 구분 | 평가 내용 |
|---|---|---|
| 차량특화성 | 필수 | 모바일 대비 차량 환경만의 독자적인 가치와 우위를 제공하는가 / 주행·정차 맥락 및 차량 기능과 유기적으로 결합되었는가 |
| 창의성 | 필수 | 기존에 없던 독창적이고 혁신적인 아이디어인가 / 운전자 및 동승자의 Pain Points & Needs가 명확히 정의되고 해결 방식이 명확한가 |
| 기술 활용성 | 필수 | Pleos Playground에서 제공하는 SDK·API를 앱의 핵심 기능과 사용 경험에 적절히 활용했는가 |
| 사업성 | 필수 | 타깃 고객이 명확하며, 사용자 확보와 지속적인 이용·확대 가능성이 있는가 (타깃 고객 분석, 예상 MAU, Retention Rate, 향후 서비스 확대 계획 등) |
| [가산점] 개발 산출물 | 선택 | 프로토타입 시연 영상(화면 녹화 포함), GitHub 저장소 링크(소스 코드 및 APK 포함) |

### 심사 절차 및 개발 결과물
- 합격팀은 공지사항으로 안내
- 1차 합격팀(20팀)은 2차 PT 심사 전까지 최종 개발 결과물 제출 (1차 제출 산출물 보완 가능)
- 2차 PT 심사 시 **실제 동작 가능한 앱 시연(에뮬레이터 구동 화면 또는 기기 시연) 필수**
- 2차 PT 심사에서 제출·시연한 결과물 기준으로 수상작 선정과 순위 확정
- 최종 선정 이후 전시 준비 기간은 추가 개발 기간이 아니라 전시·시상식용 영상 제작과 현장 시연용 APK 구동 테스트 기간. 오류 수정 등 일부 보완은 가능하나 추가 개발 여부는 최종 순위에 영향 없음
- 제출 결과물은 정상 구동·시연 가능 여부를 확인하며 필요 시 보완 요청 가능
- **추후 안내 예정**: 2차 PT 심사 기준, 수상팀(10팀) 전시 준비 기간 준수사항(수정·보완 범위, 추가 제출물과 기한)

## 10. 참가 및 출품 유의사항 (공지사항 원문 요약)

### 출품 및 접수
- 모든 출품작은 순수 창작물이어야 하며, 표절작 또는 기발표된 타 공모전 수상작은 심사 제외
- 제출 서류 내용이 사실과 다를 경우 선정 취소 가능
- 마감일 이후 제출 서류는 불인정. 파일 오류·파손 책임은 지원자
- 잘못된 개인정보 입력으로 응모가 정상 완료되지 않으면 응모자 책임
- 수정·재제출 시 기존 파일 포함 전체 제출물 + 서명 완료된 동의서 첨부, 팀원 전원 CC 해야 유효 접수
- 현대자동차그룹 임직원은 참가 가능, 최종 수상 대상 제외
- 응모자의 고의·과실로 인한 법적 문제는 응모자 책임, 입상 후 밝혀지면 수상 취소 및 상금 환수

### 심사 및 시상·현장 시연
- 세부 심사기준 및 과정 비공개
- 응모작 수와 심사 기준에 따라 시상 작품 수 조정 또는 수상작 없음 가능
- 1차 합격팀(20팀)은 2차 PT 시 실제 동작 가능한 앱 시연 필수
- 최종 10팀은 전시 구동용 최종 APK 제출 및 2027년 2월 행사 현장 참여·시상식 참석 의무

### 지적재산권(IP)
- 제3자 권리(초상권, 저작권, 디자인권 등) 침해 금지, 분쟁 시 응모자 책임
- 수상 후에도 법적 분쟁 발생 시 수상 취소 및 상금 전액 환수
- 출품 자료의 지식재산권은 응모자에게 있음. 단, 수상작은:
  - 주최측이 수상 아이디어에 대한 「통상실시권」을 가질 수 있음 (사용대가·범위·기간은 상호 협의)
  - 주최측이 결과 발표일로부터 4개월간 지식재산권 양도 등에 대한 「우선협상권」을 가질 수 있음
  - 주최자는 비영리 공익 목적으로 입상작 복제·전송 가능, 별도 합의로 2차적 저작물 작성 및 수익 창출 가능. 요강 범위를 넘는 이용은 별도 합의

### 상금 지급
- 대표 신청자에게 일괄 지급, 분할 지급 없음 (팀 내 분쟁 중재 책임 없음)
- 상금 지급 시 개인정보가 수령인과 불일치하면 당첨 취소
- 오기재로 인한 미지급은 주최 측 책임 없음
- 제세공과금(기타소득세 등)은 원천징수 후 지급

### 제출물 보관 및 폐기
- 요청 시 반환·폐기. 별도 요청 없으면 행사 종료일(2027.02.28) 후 즉시 폐기
- 수상작은 세무 신고 증빙 및 후속 지원 이력 관리를 위해 2년간 보유 후 폐기
- 기타 정하지 않은 사항은 주최 측 결정에 따름
